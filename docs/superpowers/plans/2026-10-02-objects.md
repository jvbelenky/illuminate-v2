# Objects (obstacles) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Place box (and file-loaded extruded-polygon) objects in the room so guv-calcs occludes and reflects light off them, with full CRUD in the sidebar, sync, persistence, units, and 3D rendering.

**Architecture:** Mirror the lamp/zone vertical slice: pydantic schemas + a `/session/objects` router wrapping `room.objects`; generated OpenAPI types aliased in `contract.ts`; store methods that enqueue `object-update`/`object-delete` sync commands; an `ObjectEditor.svelte` that reads the store directly; a `SceneObject3D.svelte` that authors geometry in room coordinates inside a −90° X-rotated group.

**Tech Stack:** FastAPI + pydantic v2 + guv-calcs 0.7.3 (`Object`, `ObjectRegistry`); SvelteKit / Svelte 5 runes, Threlte + three.js, Zod, MSW, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-02-objects-design.md`

## Global Constraints

- No guv-calcs changes; never commit in `~/guv-calcs`.
- Generated API contract only: run `make generate-api`; alias from `api-types.ts` in `contract.ts`. Never hand-write request/response types.
- `pnpm check` zero errors; no `@ts-ignore`.
- `.svelte` files use tabs; edit them with the `editing-svelte-files` skill (Python helper or Write), never Edit/sed.
- Editor components must not mirror store state in local `$state`.
- Every mutating handler wraps its body in `with locked_session(session):`.
- All update/delete sync goes through the sync queue; add/copy may await the API directly (as zones do).
- IDs are client-minted (`object-N`), backend 409s on collision.
- Values are in the room's current units on both sides; only `PATCH /session/units` converts.
- `CHANGELOG.md [Unreleased]` entry in the same commit as the user-facing change. No `Co-Authored-By`.
- Never inline `0.3048`.

## Review Focus

1. `reflectance + transmittance > 1` typed into the editor → backend 400 with guv-calcs' message, the toast shows it, and the store value is not silently kept out of sync forever (Task 2 test: PATCH with R=0.7,T=0.5 → 400 containing "R + T"; Task 6 test: editor sends both values in one `updateObject` call).
2. An object partly outside the room → `check-positions` lists it with `entity_type: "object"` and `nudge-into-bounds` moves it inside (Task 3 tests).
3. A stored project from before this feature (no `objects` key) → `loadFromStorage` yields `objects: []`, not a crash (Task 5 test).
4. A `.guv` written by Python with an extrusion and `face_properties` → loads, renders, and saves back with `face_properties` intact if untouched (Task 3 save/load test asserts `face_properties` round-trips).
5. Switching units with objects present → positions, dimensions and extrusion vertices in the store are the echoed converted values, not the old ones (Task 3 units test; Task 5 `changeUnits` test).
